## 一、自动化测试结果

### 1. 题库校验

命令：

```bash
node tests/questions.test.mjs
```

结果：**PASS**

```json
{
  "total": 150,
  "easy": 60,
  "medium": 55,
  "hard": 35,
  "boss": 20,
  "image": 30,
  "dialogue": 45,
  "truefalse": 35,
  "meaning": 40
}
```

校验内容：

- ID 唯一、状态为 live。
- 选项数量：四选一 4 项，真假题 2 项。
- `answerKey` 必须存在于选项中。
- 选项文本不重复、字段非空。
- BOSS 题必须为难度 3。
- 图片题必须有 `visual.emojis`。
- 题干/选项/解释长度阈值检查（无警告）。

### 2. 核心规则测试

命令：

```bash
node tests/core.test.mjs
```

结果：**PASS**

覆盖：

- 3 易 / 4 中 / 3 难抽题与第 10 题 BOSS。
- 每日挑战同日期确定性、跨日期不同。
- 全对分数 = 280（30 + 80 + 60 + 60 + 50）。
- 通关梗币 = 660（280 × 2 + 100）。
- 答错/超时扣命、生命归零、复活上限 2 次。
- 四选一提示移除 2 个错误项，真假题返回出处提示。
- 加时每局 1 次。
- 双倍只允许通关局、每局一次、幂等。
- 结算幂等，重复领取被拦截。
- 倒计时暂停/恢复不计算后台时间、加时、超时只触发一次。
- 北京时间日期/周键。

### 3. 应用无头冒烟测试

命令：

```bash
node tests/app-smoke.test.mjs
SCREEN_W=320 SCREEN_H=568 node tests/app-smoke.test.mjs
SCREEN_W=414 SCREEN_H=896 node tests/app-smoke.test.mjs
```

结果：**三档尺寸均 PASS**

覆盖流程：

- 触摸首页“开始故事”按钮进入第一章开场，逐句对白后接受挑战。
- 人物首次登场：旁白阶段无人物；嘉豪首次开口时出现；主角首次有台词时出现；首页主角在剧情开始后才显示。
- 进入第一章「宿舍」：选项卡真实绘制并通过触摸选择提交（回归测试，防止“看得到/看不到但点不了”）；10 题全对进入关卡结算，得分 280、基础梗币 660、图鉴解锁 10 条。
- 剧情关卡通关标记写入、第一章完成、下一章进度推进；结算页显示“进入校园地图”。
- 第二章「食堂」开场：芬姨首次开口时登场、主角首次台词时登场；进入第二章答题后使用芬姨提问像与专属题池，10 题按 3/4/3 出题、第 10 题为 BOSS。
- 第三章「教室」开场：李老师首次开口时登场；完成第二章后由地图解锁第三章，题目来自教室专属题池，同样按 3/4/3 + BOSS 出题。
- 双倍广告：梗币 660 → 1320，个人梗币 960 → 1620。
- 校园地图：4 个关卡节点/关卡行；第一章完成后第二章显示“可挑战”、第三章“未解锁”；顺序通关第一至三章后第三章“已通关”、第四章“未开放”；地图/节点可点开说明；首页按钮变为“进入校园地图”，并显示三章完成进度。
- 主角精灵帧：3 血 = 第 1 帧、2 血 = 第 2 帧、1 血 = 第 3 帧。
- 图鉴筛选、详情弹窗。
- 排行榜周/总/每日入口与数据。
- 每日挑战固定题单生成、完整通关、首胜 +200（总分 280 → 梗币 860）。
- 商店购买/装备皮肤。
- 设置：音效/背景音乐/振动切换、昵称修改、隐私弹窗。
- 背景音乐场景切换：首页/开场等对话/菜单场景为 relaxed，答题页（普通与剧情）为 tense，结算页回到 relaxed；设置中背景音乐默认开启、可关闭。
- 提示（梗币）、三次答错出局、广告复活、加时广告。
- 复活弹窗回归：点击弹窗内的“看广告复活”后，广告播放期间不会重开弹窗；广告完整观看并复活成功后弹窗保持关闭。
- 每日挑战广告再挑战。
- 结算幂等：重复 `grantRunClaim` 返回 `ALREADY_CLAIMED`、重复双倍返回 `ALREADY_DOUBLED`、重复进入结算页不重复加币。
- 快照恢复：普通局恢复到 `game`，剧情局恢复到 `storyGame`。
- 切后台/回前台生命周期。
- 顶部微信菜单胶囊避让：梗币与倒计时环位于胶囊左侧。
- BOSS 图片题最坏布局：选项不重叠底部按钮。
- 清除数据恢复初始状态。

## 三、待人工验收项

以下项目无法在 Node 无头环境中完全确认，需在微信开发者工具 + 真机完成：

1. 微信开发者工具能否正常编译、上传、真机预览。
2. iOS / Android 真机的 Canvas 字体、emoji、刘海安全区与触摸坐标。
3. 第一至三章剧情界面的真机视觉：透明角色边缘是否有白边、嘉豪/芬姨/李老师半身像与新对话气泡的对齐、主角放大后的三档立绘是否清晰、三张背景裁切是否合适。
4. 地图界面真机视觉：地图节点与覆盖状态圈是否对齐、关卡行/节点点击区域是否易点、第二章“可挑战”、第三章“未解锁”与第四章“未开放”提示是否清楚。
5. 剧情图片在真机的加载速度、JPG 压缩痕迹与不同屏幕的清晰度；切换关卡/重玩时缓存是否正常，三章背景切换是否残留上一章图像。
6. 真实激励视频/插屏广告：加载、无填充、提前关闭、切后台、重复点击。
7. WebAudio 合成音效在真机的可用性与音量；两套程序化 BGM（轻松/紧张）的试听、场景切换淡入淡出、设置开关。
8. `wx.shareAppMessage` 分享标题/query 与分享菜单行为。
9. `wx.showModal({ editable: true })` 修改昵称在目标基础库上的行为。
10. 本地存储容量、清除数据、快照恢复在真机上的稳定性。
11. 150 道题库的事实、敏感词、版权与表达复核。
12. 微信后台隐私保护指引、类目、备案、流量主等合规材料。
13. 低端机帧率、首屏耗时、分包/包体实测（原示例代码与图片已删除；打包忽略 `docs/tests/.claude`，当前含三章剧情透明角色、背景/地图，预计约 3MB；BGM 为程序化合成，无外部音频文件）。

## 四、已知限制

- 剧情模式当前开放第一至第三章（宿舍 / 食堂 / 教室）；第四章「图书馆」仍为地图占位（未开放）。
- 剧情背景/地图使用压缩 JPG，角色使用透明 PNG（`assets/story/`）；原始高清 PNG 在 `.claude/profile/`，不参与打包。
- 无 CloudBase / 服务端权威判题，排行榜是本地演示数据。
- 广告默认 Mock；真实广告位 ID 未配置。
- 无 Banner、题包商店、自定义分享图、头像、好友关系链。
- 每日/广告次数以设备本地时间为准。
- 昵称未接内容安全接口。
- 背景音乐为 WebAudio 程序化合成：对话/菜单场景轻松，答题场景紧张；默认开启，设置可关闭。
- 题库为演示内容，正式上线前必须人工复核。

## 五、结论

本轮 Demo 已达到开发确认文档中的“最小可上线定义（Demo 版）”，并完成剧情关卡体系的第一至第三章：
